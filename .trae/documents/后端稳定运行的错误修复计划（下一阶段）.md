## 目标
- 以“可正常运行”为首要目标，优先修复会导致 500/异常的逻辑错误和空指针问题，暂不做性能/结构优化。

## 必修复项
1. 修复聚合问题的空指针
- 问题：`service/model/metric/AnalysisResult.getIssues()` 直接 `addAll(metricResult.issues)`，当某个指标返回 `issues = null` 时抛 NPE。
- 修复：为 `metricResult.issues` 增加空值保护：为空则跳过或当作空列表。
- 影响：消除分析阶段的 500，适配所有指标的返回。

2. 单文件项目分析的健壮性
- 问题：项目包含极少文件或未能解析 AST 时，某些指标在边界分支可能返回 `issues = null` 或依赖未设字段。
- 修复：
  - 确保所有指标在任何分支都返回非空 `issues` 列表（必要时在 `FunctionLengthMetric` 等类中统一为 `new ArrayList<>()`）。
  - 在 `ProjectController.analyze` 收集 `allIssues` 前添加保护：忽略空列表或空问题对象。
- 影响：单文件项目不再出现 500，分析流程可完整结束并返回结果。

3. 文件路径与 AST 属性一致性
- 问题：各指标通过 `cu.getProperty("filePath")` 读取文件路径；当前已在分析引擎设置该属性，但个别非 Java 文件应被跳过。
- 修复：在分析引擎中当 AST 为空或非 Java 时，保持 `imports` 与 `issues` 的空安全，确保下游不崩溃。
- 影响：保证不同文件类型/异常代码段不会中断分析。

## 次要修复（可并行但不阻塞运行）
4. 接口注解清理
- 问题：`service/CodeService.java` 接口标注了 `@Service`，可能导致扫描歧义。
- 修复：移除接口上的 `@Service`，仅保留实现类注解。

5. Bean 重复定义隐患
- 问题：`Analyzer.DefaultAnalyzer`（`@Component @Primary`）与 `AnalyzerConfiguration`（`@Bean @Primary`）提供同类型 Bean，存在潜在冲突风险。
- 修复：保留单一路径（推荐：保留配置类中的 `@Bean`，移除 `@Component`），并仅保留一个 `@Primary`。
- 注：此项不影响当前运行，但建议在完成必修复后处理。

## 修改清单（最小改动）
- `service/model/metric/AnalysisResult.java`
  - 更新 `getIssues()`：遍历 `metricResults.values()` 时，对 `metricResult.issues` 进行空判断，空则跳过。
- （如发现仍有 NPE）各指标类（如 `FunctionLengthMetric`）
  - 将任何返回 `new MetricResult(..., null, ...)` 的分支改为返回空列表。
- `controller/ProjectController.java`
  - 收集 `allIssues` 前加入空判断（`fr.getIssues()` 为 `null` 时当作空）。
